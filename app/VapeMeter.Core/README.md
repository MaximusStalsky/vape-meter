# Локальное хранилище Vape Meter

Клиентское ядро `VapeMeter.Core` не зависит от Avalonia и платформенного окна. На Windows и Android можно переиспользовать `MeterStore` и `MeterSync`, передавая путь к локальной базе и ключ из защищённого хранилища устройства.

- Интерфейс читает `GetReplacements()` и выполняет операции в локальной SQLite до сетевого обмена. Данные и очередь меняются атомарно. Запись содержит UUID и дату без часового пояса. Дата замены уникальна.
- `MeterSync` сохраняет отправляемую операцию в SQLite до запроса. После потери ответа повторяет тот же UUID и то же тело. Если пользователь успел снова исправить запись, новая правка остаётся в очереди и получает версию подтверждённой операции.
- Снимок сервера хранится отдельно от локальных правок. Конфликт отображается через `SyncStatus.Conflicts` и разрешается методом `ResolveConflict`. При восстановлении базы на сервере старые локальные и уже подтверждённые записи остаются доступны для выбора. Одинаковые записи, независимо добавленные двумя устройствами, могут принять единый серверный UUID.
- SQLite-снимок сохраняется методом `Backup`. `Restore` объединяет историю и сохраняет текущие правки и известные отметки удаления. `Export` и `Import` используют версионированный JSON с UUID. Экспорт и резервная копия записываются в новый файл.
- `SeedIfEmpty` предназначен для отдельной демонстрационной базы. База хранит отметку о начальном заполнении, поэтому удалённые демозаписи не появятся при следующем запуске. Явный сброс через ResetDemo доступен только для инициализированной демобазы, которая ещё ни разу не синхронизировалась.

На отдельной временной базе Windows проверены автономные операции, настройки, резервная копия и импорт. В обмене с локальным экземпляром backend проверены пропущенный ответ, новая правка во время отправки, конфликт нескольких устройств, одинаковые даты, зависимое освобождение даты, удаление и смена набора данных.
